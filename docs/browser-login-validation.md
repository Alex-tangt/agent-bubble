## 用户会话验证

已打开项目专用 Chrome，用户确认完成登录并关闭窗口。专用 profile 中存在适用于专栏域名的登录 Cookie；诊断仅输出存在与否，没有输出或导出 Cookie 值。

这证明项目专用 Chrome 的访问限制没有因本次正常登录而解除。不能把保存登录会话、窗口关闭或 Cookie 存在当成文章可读。该路径的知乎两篇仍未通过，其他三篇此前的验收见 [文章工作流](article-workflow-validation.md)。

## 2026-10-09：内置浏览器可读的对照证据

用户提供了 Codex 内置浏览器中已打开的第二篇原始分享链接。通过浏览器工具实际读取了文章 DOM，标题为「给 Agent 加了记忆、反思、Skill，真的会变强吗？」；现有解析选择器 `.Post-RichTextContainer .RichText` 命中 3,150 字符可见正文，包含六个章节和最后的工程决策结论段，正文之后还有项目官网链接。没有重新加载用户标签页、导出浏览器凭据或读取其他页面的私有信息。

因此应将此前的结论收窄为「项目专用 Chrome 的访问路径失败」。该文章存在正常可读、可通过代码提取正文的浏览器路径；DOM 结构也与现有站点选择器一致。仅凭两种环境结果不同，仍不能确定限制的具体触发因素，不能断言为 IP、Cookie、无头模式或浏览器指纹中的某一项。

这次通过的是内置浏览器可见正文读取，并未执行独立后台 URL 抓取或真实模型总结 / 追问。Codex 的浏览器工具属于当前开发环境，不是安卓应用可直接使用的生产依赖。可继续把正常可读页面的正文采集作为来源适配器接入现有工作流；生产可用的页面采集入口仍待实现。验证元数据：`data/article-validation/2026-10-09-iab-zhihu/report.json`。

## 2026-10-09：独立 Electron 适配器接入与验收

随后创建独立 Electron 44.7.0 / Chromium 152.0.7977.130 的项目浏览器，默认运行设置、全新 profile，无手动登录，两篇原链接均 HTTP 200。正式后端已使用该 renderer 读取知乎，再交给既有 `extractArticle` 和 Pi 工作流。`npm run test:articles -- --site=zhihu --llm` 两篇真实总结 / 同会话追问通过：正文分别 9,967 / 3,152 字符，准确标题与已知结尾匹配。报告 `data/article-validation/2026-10-08T17-51-18-441Z/report.json`。

知乎登录入口也改为使用同一个 Electron 会话，独立保存于 `data/article-electron-browser/`；Playwright profile 保留供其他站点使用。实际网页按钮的打开、关闭、排队恢复、重复打开均通过：`data/browser-login-validation/2026-10-08T17-56-41-963Z/report.json`。此测试使用独立目录和测试模型，没有用户 Cookie。单元 / 协议测试共 30 项通过，包含取消、worker 崩溃后重启、错误握手拒绝，以及子进程不继承模型 key / 服务 token。

Windows Electron GUI 子进程的 stdin 会立即 EOF，原先按行读取 stdin 的接入版本提前退出。正式适配器使用只绑定回环地址、有一次性随机握手的父子进程通道；浏览器页面不接触这个通道。读取、执行 JS 与父进程请求均有截止时间，取消销毁对应窗口，finish 强制结束登录窗口，worker 失联恢复为结构化错误。远程页面保留沙箱、同源策略与上下文隔离，没有 Node / preload / 业务 IPC；网络目标仍通过公开地址检查，自动下载与权限请求被拒绝。

修复证据限定为该独立 Electron 环境通过，不能单独认定 UA、无头模式、IP 或 Cookie 为触发原因。当前尚无无桌面云端的成功证据。社区首方源码与案例见 [社区诊断](zhihu-community-diagnosis-2026-10-09.md)。

运行中服务已更新，真实 HTTP API 两篇无预先缓存的 URL 获取、真实总结与同会话追问均通过：`data/zhihu-production-validation/2026-10-08T18-08-22-179Z/report.json`。已有安卓请求契约保持兼容，无需因这次后端修复重装 APK。分发源码 / APK 凭据审计通过，生产脚本与服务未遗留调试日志。

## 已实现的出口

- 桌面网页「连接设置 → 网站登录」提供知乎重登与公众号验证。
- 来源返回登录 / 验证 / 访问限制时，原会话显示「登录或验证后重试」。
- 窗口在后台主机打开，使用项目 profile；窗口打开期间新任务保存并排队。
- 用户关闭整个窗口，或点击「关闭登录窗口并继续」，后台自动恢复执行。没有完成登录也可以退出。
- 打开失败恢复队列；正在执行任务时返回 409，保留该任务；重复点击沿用现有窗口。
- 会话有效性由实际读取检查。登录失效会在模型调用前停止，保留原会话、来源缓存和已有结果，允许重登后原会话重试。没有固定假设站点登录能维持多久。

命令行入口：

```powershell
npm run browser:login -- --site=zhihu
npm run browser:login -- --finish
npm run browser:login -- --status
```

API 见 [MVP 接口](mvp-api.md)。登录接口沿用服务连接凭据，站点为固定枚举，不接收任意导航 URL。Cookie 留在专用 profile，模型收到的仍只是取得并校验后的正文。
