# Agent Bubble 手机连接与调试指南

适用于本项目现有 APK、Windows 电脑和 USB 连接的真实安卓手机。你负责在手机上体验功能，构建、安装更新和分析日志可以交给开发 Agent；日常测试不需要 Android Studio。

## 1. 先理解连接关系

```text
手机 Agent Bubble
    ↓ USB 数据线 + ADB 端口转发
电脑上的后端：http://127.0.0.1:8787
    ↓ 电脑联网抓取文章、请求模型
保存任务、总结和对话 → 手机查看结果
```

- APK 是安装在手机上的应用；后端是运行在电脑上的程序，两者需要分别准备。
- ADB 是电脑与已授权手机之间的调试工具。本项目已经装好，不用另外下载。
- “端口转发”是把手机访问 `127.0.0.1:8787` 的请求送到电脑后端。仅插上数据线还不够，必须建立转发。
- 当前采用 USB 连接。手机不必和电脑连同一个 Wi-Fi；电脑需要联网，才能抓文章和调用模型。
- 电脑睡眠、关机或者后端退出，会影响任务执行。手机退出页面后，电脑已经接收的任务仍可继续。
- 拔掉 USB 后，手机暂时无法通过这个地址接收新结果；重新连接后能取回电脑上已保存的结果。当前还没有配置脱离电脑使用的远程入口。

| 项目 | 本机使用的值 |
|---|---|
| 项目目录 | `D:\path\to\agent-bubble` |
| 手机序列号 | `DEVICE_SERIAL`，更换手机后需要重新查看 |
| 手机“服务地址” | `http://127.0.0.1:8787` |
| 电脑后端状态页 | `http://127.0.0.1:8787/health` |
| 电脑网页客户端 | `http://127.0.0.1:8787/` |

`http://10.0.2.2:8787` 是安卓模拟器使用的地址。USB 连接真实手机时使用表格中的 `127.0.0.1`。

## 3. 首次准备：电脑和手机分别做什么

### 3.1 在电脑打开 PowerShell，进入项目目录

可以从 Windows 开始菜单搜索“PowerShell”打开，然后复制执行：

```powershell
Set-Location 'D:\path\to\agent-bubble'
```

后面的命令都在这个目录执行。复制时保留命令中的 `&`、引号和完整路径即可，不需要理解开发语法。

### 3.2 确认电脑后端运行

在**电脑浏览器**打开：

```text
http://127.0.0.1:8787/health
```

正常应看到：

```json
{"status":"ok","version":"0.1.0"}
```

能看到这个响应，就已经有后端在运行，无需再启动一个。

如果打不开，且后端确实没有运行，在项目目录执行：

```powershell
& 'node' --env-file-if-exists=.env dist/server/index.js
```

这个窗口会持续运行后端。保留窗口，另开一个 PowerShell 执行连接命令；关闭后端窗口会停止服务。当前电脑的依赖、模型 key 和编译结果已准备好，不需要重复安装依赖、创建 `.env` 或重新编译。

如果出现 `EADDRINUSE`，一般说明端口已被占用。先检查状态页，不要反复启动服务，也不要结束所有 Node 进程。

### 3.3 在手机开启 USB 调试并授权电脑

当前手机已经完成这一步。换手机或者授权失效时再做：

1. 在手机设置中打开“开发者选项”和“USB 调试”。不同系统菜单位置不同，可以在设置里搜索。
2. 使用能传数据的数据线连接电脑，解锁手机。
3. 如果出现“允许 USB 调试”的电脑授权弹窗，确认是你的电脑后允许，可以勾选始终允许。
4. 在电脑执行：

```powershell
.\.tools\android-sdk\platform-tools\adb.exe devices -l
```

当前手机的正常结果包含：

```text
DEVICE_SERIAL    device
```

关键是序列号后面的 `device`。`unauthorized` 表示电脑未获授权；`offline` 表示连接异常；只有标题没有设备行，表示电脑没有识别到手机。

### 3.4 安装主 App：已经安装则跳过

手机桌面能找到 Agent Bubble 就不用重装。本次知乎修复只更新了电脑后端，现有 APK 可以继续使用。

首次安装或有新的客户端 APK 时，在电脑执行：

```powershell
.\.tools\android-sdk\platform-tools\adb.exe -s DEVICE_SERIAL install -r .\artifacts\agent-bubble-0.1.0-debug.apk
```

看到手机上的 USB 安装提示时允许，电脑输出 `Success` 表示安装成功。小米 / HyperOS 可能还要求开启“USB 安装”。`-r` 用于覆盖安装，正常情况下保留原有应用数据。

### 3.5 建立 USB 转发：每次重连后执行

在电脑执行：

```powershell
.\.tools\android-sdk\platform-tools\adb.exe -s DEVICE_SERIAL reverse tcp:8787 tcp:8787
```

这条命令成功时通常没有文字输出。需要确认时执行：

```powershell
.\.tools\android-sdk\platform-tools\adb.exe -s DEVICE_SERIAL reverse --list
```

正常结果包含 `tcp:8787 tcp:8787`，前面可能显示 `UsbFfs`。电脑 / 手机重启或 USB 重连后，先重新执行转发命令。

### 3.6 首次保存 App 连接设置

**已有设置的手机：**打开 Agent Bubble，等待几秒。顶部显示“个人 Agent 已连接”就可以直接测试，不需要重新填写凭据。

**全新安装或凭据变化：**本机已有自动配置脚本，可以在电脑执行：

```powershell
& 'node' --env-file-if-exists=.env scripts/connect-phone.mjs DEVICE_SERIAL
```

执行时保持手机解锁，并允许手机上出现的 USB 安装提示。脚本会安装用于配置的调试伴随包，设置服务地址和连接凭据，验证连接，最后打开主 App。看到以下文字表示自动配置通过：

```text
Phone connected to the personal backend. Model key remains on the computer.
```

如果返回 `INSTALL_FAILED_USER_RESTRICTED`，处理手机上的 USB 安装限制后重新执行；如果提示缺少 AndroidTest APK，请让开发 Agent 准备辅助包，不需要你研究构建步骤。已有有效设置时不必运行这个脚本。

也可以手动设置：

1. 手机 App 右上角齿轮 →“连接个人 Agent”。
2. “服务地址”填写 `http://127.0.0.1:8787`。
3. “连接凭据”填写电脑 `.env` 中的 `AGENT_BUBBLE_TOKEN` 的值。
4. 点击“连接”，等待顶部出现“个人 Agent 已连接”。

电脑上有一个复制连接凭据的脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\copy-connection-token.ps1
```

它只复制到**电脑剪贴板**，不会自动填入手机。手动设置需要你通过自己的可信方式把这段值填入手机，所以本机首次配置优先使用自动脚本。这里填写的是服务连接凭据；`DEEPSEEK_API_KEY` 留在电脑，不填写到 App。

## 4. 以后每次开始测试的最短流程

1. 电脑浏览器打开状态页，确认后端运行；打不开时按 3.2 启动。
2. 手机解锁，USB 连接电脑。
3. 电脑 PowerShell 执行下面三行：

```powershell
Set-Location 'D:\path\to\agent-bubble'
.\.tools\android-sdk\platform-tools\adb.exe devices -l
.\.tools\android-sdk\platform-tools\adb.exe -s DEVICE_SERIAL reverse tcp:8787 tcp:8787
```

4. 手机打开 Agent Bubble，确认“个人 Agent 已连接”。
5. 开始第 5 节的功能测试。

已保存的地址和凭据会保留。日常无需重装 APK、重新配置模型 key 或安装调试伴随包。

## 5. 手机功能测试：按这个顺序来

建议先用完整 App 页面测试，再打开悬浮窗。每次先提交一项、查看结果，再进入下一项，方便定位问题。

### 测试 A：连接与历史结果

1. 打开 App，顶部应显示“个人 Agent 已连接”。
2. 点击“最近任务”。
3. 打开已有的知乎文章任务，检查能否看到总结和来源信息。

这一步不用创建新总结，主要确认手机能读取后端数据。历史任务包含之前的调试记录；旧失败记录仍可能存在，新修复不会自动修改它们。

### 测试 B：直接粘贴正文，验证模型处理

1. 点击“交办”，选择“正文”。
2. 在“内容来源”粘贴以下测试正文：

```text
本周项目会议决定，第一阶段先完成网页文章抓取、总结和同一会话追问。
手机端负责提交来源、显示任务状态和展示结果，电脑后端负责获取正文、调用模型和保存对话。
文章工作流跑通后，再完善悬浮窗布局和分享交互。
视频画面理解暂时放到下一阶段，本阶段先验证字幕和音频转写体验。
```

3. “交给 Agent 的任务”填写：`总结为三个要点，并指出暂缓的功能。`
4. 点击“交给 Agent”。
5. 观察状态由“已接收 / 处理中”变成“已完成”。页面应显示总结，以及“基于正文 · … 字符 · 已保存”。

通过标准：总结能反映原文内容，明确指出视频画面理解暂缓。如果这一步成功，说明连接、模型调用和结果回传基本正常。它会产生少量模型 API 用量。

### 测试 C：文章链接抓取与总结

1. 点击“交办”，选择“链接”。
2. “内容来源”先粘贴这篇已验证的知乎链接：

```text

```

3. “交给 Agent 的任务”填写：`总结核心观点，区分实验结论和作者建议，并列出三个值得追问的问题。`
4. 点击“交给 Agent”，观察获取内容、总结和完成状态。
5. 检查来源标题是否是“给 Agent 加了记忆、反思、Skill，真的会变强吗？”，总结是否讨论记忆、反思和 Skill 的实际作用。

### 测试 D：收到总结后继续对话

1. 留在刚才文章的“结果与追问”页面。
2. 在底部“继续追问这份内容…”输入：`如果只做一个自用的文章总结助手，哪些建议值得先采用？请结合本文解释。`
3. 点击发送箭头。
4. 新的回答应出现在同一个结果页面，之前的总结仍保留。

通过标准：不需要再贴链接，回答仍基于原文章。回到“最近任务”后，打开该文章可以看到同一会话里的总结和追问。

### 测试 E：从其他 App 分享到 Agent Bubble

1. 在手机浏览器或知乎打开文章。
2. 点击文章的分享按钮，找到系统分享菜单；有些 App 需要先点“更多”。
3. 选择 Agent Bubble。
4. 应进入交办页面，“内容来源”已经带入分享的链接或文案。
5. 检查来源，填写指令，点击“交给 Agent”。

如果分享菜单没有 Agent Bubble，先用“复制链接 → 打开 Agent Bubble → 粘贴”确认文章任务本身可用，再记录是哪一个 App 的分享菜单缺少入口。

### 测试 F：悬浮球与悬浮页面

1. 在 App 底部点击“开启悬浮窗”。
2. 首次会进入系统权限页，允许 Agent Bubble 显示在其他应用上层。
3. 返回 App，**再点一次“开启悬浮窗”**。
4. 通知权限弹窗出现时允许，用于任务完成提醒。
5. 回到桌面或打开浏览器，检查悬浮球是否可见；拖动它调整位置。
6. 点击悬浮球，检查能否展开交办、最近任务、结果与追问页面。
7. 提交一个链接任务，出现“已接收 / 处理中”后点击收起按钮。
8. 之后点悬浮球 →“最近任务”→刚才的文章，检查结果和追问。

当前浮窗接收你分享或粘贴的链接、正文、字幕；不会自动读取当前 App 的屏幕内容。系统授权页返回后需要再点击开启，是当前版本的正常操作。

### 测试 G：离开页面后后台继续处理

1. 提交任务，等到页面明确显示“已接收”或“处理中”。
2. 收起浮窗或回到其他 App，保持电脑后端运行。
3. 再打开 Agent Bubble →“最近任务”→刚才的任务。
4. 检查状态是否更新、结果是否能取回。

USB 断开后电脑已接收的任务仍可继续，但手机需要重连并恢复转发才能获取新状态。未取得回执的请求可能处于待发送状态，不能仅凭点过按钮就认定任务已提交。

完成通知依赖开启的浮窗服务轮询、通知权限以及手机系统是否允许服务运行。没有收到通知时，先重新打开 App 查看任务；通知缺失不等于后端未完成。若浮窗频繁消失，再检查该 App 的后台运行 / 电池限制设置。

### 测试 H：错误、补充和重试

- **请求尚未成功提交：**出现“重试发送已保存的任务”，恢复连接后点击它，继续发送同一份请求。
- **任务已经被接收但失败：**在结果页记录错误文字，解决原因后点击“原会话重试”。
- **需要补充内容：**点击“补充正文 / 字幕”。补充文章时选择“正文”，粘贴正文，填写要求并点击“补充并继续”；视频则选择“字幕”并提供字幕或转写。
- **想停止当前任务：**运行期间点击“停止本次处理”。这会明确取消任务；普通收起页面不会取消。

同一结果里的正常追问无需重新抓取原文章。不要用卸载 App、清除数据或反复新建任务作为第一种排错方式。

## 6. 常见问题快速定位

| 现象 | 优先检查 / 操作 |
|---|---|
| ADB 没有手机设备行 | 解锁手机，检查 USB 调试；换能传数据的数据线或 USB 口 |
| `unauthorized` | 在手机确认电脑的 USB 调试授权；未出现提示时先重新插拔 |
| `offline` | 重新插拔数据线，解锁手机，再运行 `adb devices -l` |
| `INSTALL_FAILED_USER_RESTRICTED` | 手机的 USB 安装权限或安装提示未通过；主 App 已安装且设置有效时跳过辅助包配置即可 |
| 电脑状态页打不开 | 后端未启动、退出或电脑睡眠；按 3.2 启动并检查错误 |
| 电脑状态页正常，App 显示离线 | 重跑 USB 转发；检查 App 地址是 `http://127.0.0.1:8787`，确认线还连接着 |
| 提示“连接凭据无效” / 401 | 连接 token 与后端不一致；重新运行配置脚本或更新“连接凭据” |
| 输入正文成功，但链接失败 | 连接和模型基本正常，重点看具体网站抓取错误 |
| 一直“已接收” | 默认最多 3 个独立任务并发；同会话追问按顺序、未缓存视频一次一个。已占满对应槽位，或文章网站登录窗口未关闭时会排队 |
| 提示网站登录、验证或访问限制 | 在运行后端的电脑网页客户端处理“连接设置 → 网站登录”；关闭整个登录窗口，再到原会话重试 |
| 手机已登录知乎，电脑仍抓取失败 | 手机与后端浏览器的登录状态独立，后端不会自动继承手机登录 |
| 公众号获取较慢 | 观察进度文字，等待抓取结束；不要连续重复提交。失败时保留完整错误 |
| B 站字幕不可用 | 先在电脑运行 `npm run bilibili:login` 完成登录；仍无字幕时使用配置好的 Qwen 云端转写。选用本地模式且模型未就绪时运行 `scripts/setup-asr.ps1` |
| B 站提示没有公开音轨 / 超过转写上限 | 检查访问权限，选择较短分 P，或补充字幕 / 转写；重装 App 不会解决 |
| 开启权限后没有悬浮球 | 返回 App，再点击一次“开启悬浮窗”；检查是否仍被系统权限或后台限制阻挡 |
| 没有完成通知 | 先查“最近任务”；检查通知权限、浮窗服务和电池限制 |

当前 App 打开或浮窗服务运行时，约每 4 秒刷新一次状态，所以结果可能稍晚几秒出现。普通任务默认最多执行约 5 分钟；B 站首次获取与转写默认总时限 30 分钟，单 P 转写上限 60 分钟；多个任务排队的等待时间另外计算。视频可观察“读取字幕 / 下载音轨 / 上传音轨 / Qwen 正在云端转写 / 生成回复”；本地模式显示已识别的时间点。已有视频来源的追问复用缓存，不再次下载和转写。

2026-10-09 登录后的两条测试视频均取得平台字幕，首次获取全文约 4 秒 / 3 秒，不含模型生成总结的时间。可以重新分享原链接创建新会话，或查看“最近任务”中最新的平台字幕总结，再追问最后两分钟的内容。现在已配置 Qwen，无可用字幕时走云端；10分03秒原音轨的独立云端验收获取全文约 17–21 秒，详见 [云端验收](qwen-asr-validation.md)。其他视频不保证相同耗时，也可以同时提交文章，验证它能独立完成。

## 7. 后续版本怎么一起调试

- **只改电脑后端：**开发 Agent 更新、验证并重启后端，你在手机重试任务。一般不需要重新安装 APK。
- **修改手机界面或交互：**开发 Agent 构建新 APK，再覆盖安装到手机；你按对应测试步骤体验。
- **改完后的复测：**先确认连接，再复测修改的功能和相关操作，记录预期与实际差异。

反馈问题时，提供下面这些信息即可：

```text
测试项目：链接总结 / 追问 / 分享 / 悬浮窗 / 通知等
来源链接：
输入的任务指令：
操作顺序：例如“分享链接 → 填要求 → 交给 Agent”
提交时间：
界面状态和完整错误文字：
预期结果：
实际结果：
可选截图：请遮住连接凭据和无关私人信息
```

最有助于定位的是“可重复的操作步骤 + 原始链接 + 完整错误”。模型总结质量、网站抓取失败和手机布局问题可以分别记录。
